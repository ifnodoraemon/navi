# Navi Non-Negotiable Principles (The Zen of Navi)

本宪法是 Navi 的第一性原理。它约束产品、架构、Prompt、能力、记忆和自进化行为；若实现与本原则冲突，必须修改实现或明确修订原则，不能用局部补丁掩盖冲突。

## 1. 模型拥有语义决策 (Model-Owned Semantics)

- **支架，而非代替决策**：运行时向模型提供当前事实、可用能力和约束，不用关键词路由、固定意图分类、业务工作流或系统生成的“下一步建议”替模型理解用户。
- **模型决定做什么**：目标解释、能力选择、参数、澄清、语义恢复路径和用户回复由模型决定。Checker 可以独立判断证据是否充分，但不替 Planner 选择下一步。
- **运行时决定什么被允许**：Schema、能力可见性、权限、审批、沙箱、预算、并发、取消和无进展边界由确定性代码执行。模型不能扩大自己的权限。
- **不要伪造用户意图**：运行时不得生成合成用户消息、隐藏 fallback 回答或默认业务选择来推进目标。

## 2. 事实与状态是认知底座 (Evidence and State as Substrate)

- **状态记录事实，不裁决语义**：数据库状态是已观察生命周期、授权和效果的权威记录，但它不是用户意图或下一步行动的语义权威。
- **工具只观察或执行**：工具返回结构化事实、来源、效果和错误，不输出 Navi 编写的建议、业务判断或下一步计划。第三方返回的 recommendation 字段只能作为带来源的外部数据。
- **环境必须实测**：路径、系统、服务和外部状态必须通过能力观察；模型和运行时都不能脑补。
- **完成必须有证据**：模型可以提出完成，Checker 和运行时只根据目标验收条件及真实执行证据确认；Trace 是审计证据，不是活跃状态本身。

## 3. 统一循环与模型恢复 (Unified Loop, Model-Owned Recovery)

- **一个循环协议**：对话、查询、控制和长期目标共享 Observe → Plan → Act → Evaluate 协议，可按成本与持久化需要采用不同配置，不建立产品专用旁路。
- **失败返回事实**：能力失败、验证拒绝和资源限制应成为下一轮模型可见事实。运行时只判断是否仍有重规划额度；模型决定换能力、改参数、补事实、澄清或说明阻塞。
- **暂停后仍是同一任务**：审批、用户澄清、连接器交付和资源等待通过 Durable StateGraph 暂停/恢复，完整保留身份、约束、授权范围和证据。
- **阻止机械循环**：预算、超时、重复进展签名和取消是治理边界，可确定性地停止无效执行，但不能替模型选择语义路线。

## 4. 受治理的自主性 (Governed Autonomy)

- **审批是硬状态**：聊天中的授权表达不是执行许可；敏感效果必须匹配持久、限域、可审计的审批。
- **策略信封不可放宽**：入口创建的身份、能力范围、权限上限、工作区和批准授权必须贯穿计划、执行、暂停、恢复与后台运行；内层只能收紧。
- **失败关闭**：边界不明确、审批缺失、证据不足或效果提交失败时，必须暂停或失败，不得推测成功。
- **目标不等于自我保护**：系统服务用户目标，但永远不能为完成目标而绕过安全、权限或用户控制。

## 5. 正交扩展与最小特权 (Orthogonal Extensions)

- `tools`：观察或执行，并返回事实。
- `capabilities`：稳定、可发现、可校验、受策略治理的调用契约。
- `skills`：给模型提供专业说明和工作方法；可以携带脚本、模板或资产，但所有真实执行仍须经过 capability、沙箱、权限和审计边界。
- `plugins`：安装和组合 skills、能力代码、依赖与集成，不自动获得额外权限。
- `hooks`：观察或确定性地拦截生命周期，不替模型作业务选择。
- `connectors`：负责渠道认证、传输和呈现，不改变核心语义或权限模型。

这些扩展可以组合，但不得跨越彼此的权威边界。核心能力必须能在无浏览器、无特定连接器的 headless/CLI 环境中运行、检查和测试；持久化能力不要求“无状态”。

## 6. 代码、文档与进化 (Code, Docs, and Evolution)

- **代码是运行事实，文档是当前契约**：Principles、Requirements、Architecture 和安全决策应长期保留并与实现同步；完成后的临时计划、重复 TODO 和失效修理记录应删除。
- **拒绝兼容错误架构**：旧内部契约若与当前产品方向冲突，应显式迁移或删除，不用隐式兼容层延续技术债。
- **全局设计优于局部补丁**：能力问题修能力与 Schema，状态问题修控制面，不能向全局 Prompt 注入个案补丁。
- **进化可审计、可撤销**：代码、Prompt、记忆和策略变化必须有来源、差异、验证和恢复路径；记忆必须类型化、限域、可撤销并显示冲突。
- **防御匹配风险**：按风险使用 Schema、allowlist、沙箱、结构化解析、策略检查和人工审批，不把某一种实现技术当作所有场景的普遍答案。
